#### Description:

StudyTrack is a web application designed to help students organize courses, remember deadlines, keep subject notes, and understand their academic progress. I chose this project because students often receive grades in very different ways depending on the professor. One course might calculate the final grade from exams and laboratories, while another might use homework, quizzes, assessments, participation, and projects. Many existing simple planners can remember a due date, but they do not adapt their grade calculations to these different systems. StudyTrack brings scheduling and flexible grade tracking together in one interface.

The application supports two grading methods. A course using total points calculates its current result from all earned points divided by all available points. A course using weighted categories lets the user create any categories needed and assign each one a percentage. For example, a user could create Exams at 80 percent and Labs at 20 percent, but these names and values are not built into the program. Every course can have a completely different structure. The current weighted grade only uses categories that already contain graded work, so future empty categories do not incorrectly reduce the displayed grade to zero. The course page also displays the current average inside each active category and warns the user when category weights do not total 100 percent.

The landing page offers registration, login, and a guest mode. Guest mode makes it possible to try the program immediately without creating an account. A guest can later choose Save Progress, provide a username and password, and convert the same profile into a permanent account without losing courses or activities. Registered profiles are stored in the application database and can be accessed again by logging in. If the project is hosted on an internet-accessible server, this account design also makes it possible to use the same profile from another device. Passwords are never stored directly; Werkzeug creates a secure password hash.

The dashboard summarizes the total number of activities, completed activities, overdue work, and completion percentage. It also displays each course with its current grade and lists upcoming or overdue activities from the next fourteen days. The Courses page presents all classes as color-coded cards. Inside an individual course, the user can create and delete grading categories, add activities, enter scores, mark work complete, and maintain general course notes. Activities may represent anything, including homework, labs, quizzes, projects, or exams. They can be edited or deleted, and deleting a category safely leaves its activities as uncategorized rather than destroying the work.

The Calendar page is implemented with JavaScript. Flask sends the signed-in user's dated activities to the template as JSON, and JavaScript builds a monthly calendar in the browser. Previous, next, and Today controls change the visible month without reloading the page. Each event uses the color of its course and links directly to the editing screen. Completed events remain visible with a crossed-out appearance. JavaScript also adds confirmation dialogs before destructive actions such as deleting a course, category, or activity.

`app.py` contains the Flask routes, authentication logic, validation, database access, grade calculations, and ownership checks. The ownership checks are important because they ensure that one user cannot view or change another user's records simply by altering a number in a URL. `schema.sql` defines the users, courses, categories, and items tables, as well as foreign keys and indexes. Foreign-key cascade behavior removes dependent data when a course is deleted, while deleting a category uses `SET NULL` to preserve its activities.

The `templates` directory contains the Jinja templates. `layout.html` provides the shared navigation and message area. `landing.html`, `login.html`, and `register.html` handle entry into the application. `dashboard.html` and `courses.html` summarize academic information. `course.html`, `course_form.html`, and `item_form.html` provide the main editing interface. `calendar.html` provides the structure and data for the interactive calendar. The `static` directory contains `styles.css`, which defines the responsive dark navy, violet, and turquoise visual system, and `app.js`, which implements calendar navigation and confirmation dialogs.

One design decision was to keep both grading systems instead of forcing every professor's rules into weighted categories. Total-points courses are easier to configure when every activity simply contributes points, while weighted mode is necessary when categories have different importance. Another decision was to store dates as ISO-formatted text in SQLite. The `YYYY-MM-DD` format sorts correctly and is easy for both Python and JavaScript to interpret. The interface is responsive: cards rearrange on smaller screens and the calendar becomes horizontally scrollable so that its seven-column layout remains understandable.

ChatGPT was used as an AI assistant to help plan the initial database structure, draft portions of the code, and explain testing strategies. This assistance is disclosed in comments in the project files. I reviewed, tested, understood, and personalized the implementation, and I made the final decisions about the project's purpose, features, grading flexibility, and visual direction.

Before submitting, I tested account registration, guest conversion, login, course creation, both grading modes, categories, scored and unscored activities, overdue dates, completion toggles, editing, deletion, notes, and calendar navigation. StudyTrack solves the practical problem of having academic information scattered across different systems by presenting the most useful parts in one focused application.
